## Направления аудита и первоначальные находки

### 1. Резервные копии
- `src/backup.mjs`, `parseBackup`: проверяет только `app`, `version` и что поля — массивы. Значения записей (давление, сахар, вес, даты) не проверяются. Файл с нечисловыми значениями пройдёт, ошибка проявится позже при показе или экспорте.
- `App.js` (восстановление, около строк 516–518): данные `records`, `meds`, `intake` полностью заменяются. Есть предупреждение, но нет подсчёта записей и нет автоматической копии текущих данных перед заменой.
- Файл читается целиком в память; лимита размера нет.
- Риск: потеря существующих записей при восстановлении неподходящего или повреждённого файла.

### 2. Подписки
- `App.js`, `refreshStoreEntitlement`: статус перепроверяется только при подключении магазина. При возврате в приложение (`AppState`) не проверяется. В коде `AppState` не используется.
- Офлайн: при ошибке сети сохранённый статус Pro остаётся. Срока давности у сохранённого статуса нет, поэтому Pro может остаться после истечения подписки, пока приложение не подключится к магазину.
- Возврат покупки (refund) и период отсрочки оплаты (grace period) явно не обрабатываются.
- Сценарии покупки и восстановления проверены только на уровне чистых функций (`hasActiveRuStorePurchase`, `buildSubscriptionRequest`). Сами вызовы магазинов не покрыты тестами.

### 3. Health Connect
- Импорт: дедупликация только по `metadata.id` (`seen` в `hc-imported-v1`). Список растёт без ограничения.
- Ручная запись и импортированная из «Здоровья» запись одного измерения не сопоставляются: возможны дубли.
- Правка записи, которая уже отправлена в Health Connect: повторная отправка с увеличенным `clientRecordVersion` ожидает upsert. На устройстве не проверено.
- Чтение: без разрешения на чтение импорт падает, пользователь видит ошибку. Повторный запрос разрешения выполняется только при синхронизации.
- `readRecords`: `pageSize` 1000, окно 90 дней при первом импорте и 7 дней после. При большом объёме синхронизация идёт в UI-потоке без индикатора прогресса.

### 4. Защита медицинских данных и резервных копий
- Резервная копия — JSON с данными о здоровье в открытом виде. Пользователь отправляет её любому приложению через «Поделиться». Шифрования и предупреждения о хранении нет.
- Данные в AsyncStorage не зашифрованы.
- Логов с данными в коде приложения нет (проверено поиском по `console.*`).
- Юридически: данные о здоровье относятся к особой категории по 152-ФЗ. Если появится сервер, понадобятся требования к хранению в России. Вопрос к юристу.

### 5. Безопасный CSV-экспорт
- `toCsvRecords` (`src/measurements.mjs`, около строки 111): свободного текста в полях нет. Дата в ISO, тип, единицы и контекст берутся из словарей, значения числовые. CSV-инъекция (`=`, `+`, `-`, `@`) сейчас невозможна.
- Риск появится, если добавить заметки или название лекарства в CSV. Нужны экранирование и тест.
- BOM добавляется в `App.js`, отдельного теста на него нет.

### 6. Конфигурация публикации и юридические документы
- `app.json`: `com.example.bptracker` в bundle ID и package.
- Плейсхолдеры в `docs/privacy-policy.md`, `docs/terms.md`, `docs/store-listing.md`. По `scripts/check-release.mjs`: 3, 3 и 1.
- Пустой `consoleAppId` в плагине `./plugins/withRuStorePay` — оплата в RuStore не заработает.
- GitHub Pages не включены: адреса из `src/links.mjs` недоступны.
- Нет `extra.eas.projectId` и сервисного ключа Google Play.
- Открытые вопросы: дата вступления в силу, юрисдикция (поставлена Российская Федерация, требует подтверждения), контакт.

### 7. Тестирование
- Bluetooth: разбор пакетов покрыт тестами на синтетических данных. Реальный прибор не проверен. Поиск, подключение и запросы разрешений не покрыты.
- Уведомления: расписание (`reminderSlots`) покрыто тестами, постановка в систему — нет. На устройстве не проверено.
- Android: release APK собран, установка и работа не проверены, кроме базового сценария.
- iOS: только бандл. Сборка и запуск невозможны без Mac и EAS.
- Health Connect, RuStore, покупки: на устройстве не проверены.

## Критерии приёмки для этапа исправлений
- **P0 (резервные копии):** файл, который не проходит строгую проверку, не меняет ни одну запись; перед восстановлением создаётся копия текущих данных; при ошибке импорта текущие данные сохраняются. Есть тесты повреждённых, неполных и некорректных файлов.
- **P1 (подписки):** Pro перепроверяется при возврате в приложение (`AppState`); локальный офлайн-статус имеет срок давности; тесты переходов между состояниями.
- **P1 (Health Connect):** повторный импорт не создаёт дублей; ручные и импортированные измерения сопоставляются; неудачная валидация не теряет запись и повторяется; тесты дубликатов и повторных запусков.
- **P1 (медицинские данные):** описаны реальные риски открытого JSON; предложено решение для Android и iOS; шифрование не внедряется без проверки совместимости, ключей и сценария восстановления.
- **P2 (релиз):** идентификатор приложения и конфигурация RuStore проверены; незаполненные поля документов перечислены; нативные зависимости проверены сборкой.

## Правила
- Не утверждается успех без запущенных тестов.
- Существующие тесты не отключаются.
- Медицинские пороги не меняются без обоснования и тестов.
- Секреты и реальные медицинские данные в репозиторий не добавляются.
- Каждый этап — отдельный diff, тесты и отчёт.
- Слияние в рабочую ветку выполняет владелец проекта.

# Защита медицинских данных: риски и решение

Документ описывает, где данные о здоровье лежат и кто может до них добраться. Статус: анализ и предложение. Шифрование копий не внедрено; его включают после проверки, как описано ниже.

## Где лежат данные сейчас
| Место | Что хранится | Кто может получить |
|---|---|---|
| AsyncStorage (`health-records-v2`, `meds-v1`, `intake-v1`, `health-units-v1`) | все записи в открытом виде | доступ к файлам приложения без root; облачная копия ОС (см. ниже) |
| `restore-undo-v1` в AsyncStorage | снимок данных до последнего восстановления | то же |
| Экспорт (JSON, CSV, PDF) | открытый файл | любое приложение, которое пользователь выбрал в «Поделиться» |
| Временная папка приложения (`Paths.cache`) | копии файлов экспорта и выбранных для восстановления | доступ к кэшу приложения |

## Риски
1. **Облачная копия Android.** В манифесте было `android:allowBackup="true"`. Google Auto Backup мог сохранить данные приложения в Google Drive. **Исправлено:** `android.allowBackup: false` в `app.json`. Проверка: `AndroidManifest.xml` после prebuild.
2. **Облачная копия iCloud (iOS).** Данные приложения по умолчанию попадают в резервную копию iCloud. Исключить каталог из копии можно только нативным кодом (атрибут `NSURLIsExcludedFromBackupKey`). **Не сделано:** нужна проверка на Mac или через EAS.
3. **Файлы экспорта.** Открытый JSON отправляется любому приложению, которое пользователь выберет. Предупреждение перед экспортом добавлено. Временный файл удаляется сразу после отправки. Файл, выбранный для восстановления, тоже удаляется после чтения.
4. **Открытый JSON.** Копия не защищена паролем: тот, кто получит файл, получит все данные.
5. **Права на устройстве.** Данные в AsyncStorage не зашифрованы. Это стандарт для React Native, но для данных о здоровье стоит признать риск: украденное разблокированное устройство раскрывает записи.

## Варианты защиты копий
| Вариант | Плюсы | Минусы | Статус |
|---|---|---|---|
| A. Отключить облачную копию Android и предупреждать при экспорте | просто, без новых библиотек, работает на Android и iOS | копия остаётся открытой | внедрено |
| B. Шифровать копию паролем пользователя (AES-256-GCM, ключ из пароля через PBKDF2 или Argon2) | файл безопасен даже при утечке | нужна нативная криптобиблиотека (в `expo-crypto` шифрования нет); при утере пароля данные не восстановить; нужны тестовые векторы и совместимость Android/iOS | **не внедрено**, нужно решение владельца |
| C. Шифровать весь AsyncStorage ключом из Keystore/Keychain | защищает и рабочие данные | требует нативных модулей, миграции данных и обработки потери ключа | не внедрено |

## Рекомендация
1. Оставить вариант A (сделано).
2. До внедрения B проверить: выбор библиотеки (поддержка Android 8+ и iOS, аудит), схему ключа и формат файла, сценарий восстановления на новом телефоне, поведение при потере пароля. Всё это проверяется тестами на векторах и вручную на двух устройствах.
3. Вариант C рассматривать только с отдельным решением владельца, потому что он меняет хранение всех данных.

## Что нужно проверить вручную
- Android: после установки сборки с `allowBackup=false` облачная копия не содержит данных приложения.
- iOS: после выполнения пункта 2 рисков каталог с данными исключён из копии iCloud.
- Экспорт: предупреждение показывается, временный файл не остаётся в кэше после отправки.

# Журнал проверок

Среда: песочница, 4 общих CPU, 15 ГБ RAM, PostgreSQL 16 + PostGIS 3.4, Python 3.11, Node 22, Chromium
(SwiftShader WebGL) для Playwright. **Внешняя сеть закрыта** (открыты только npm, PyPI, GitHub, apt),
поэтому всё ниже проверено на синтетических источниках devstand и офлайн-подмножестве GeoNames.
«Проверено» здесь значит: запущено, результат наблюдался, цифры получены прогоном, а не оценкой.

## Критерий готовности (Playwright, `frontend/e2e/acceptance.mjs`)

1. Открыть Землю: глобус, пузыри по континентам.
2. Страна: поиск «Россия» → панель страны.
3. Регион: «Краснодарский край», 23 события, «Где происходит» с дочерними местами.
4. Крупный город: «Краснодар» (омоним Краснодарского края выбирается по контексту в выдаче).
5. Малый город: «Горячий Ключ».
6. Посёлок или деревня: «хутор Каштаны» (600 жителей) — лента из 1 события.
7. Точка: «станица Динская».
8. Связанные новости: 3 события в Динской.
9. Несколько разных источников: пожар в Динской, 7 источников (Telegram ×2, СМИ ×2, МЧС, YouTube, федеральное агентство).
10. Объединённые дубли: пересылка Telegram помечена копией; «7 источников · 6 независимых».
11. Открыть оригинал: ссылка ведёт на страницу поста на стенде.
12. Таймлайн: ≥5 записей — первое сообщение, пересылка, отчёт МЧС, обновления.
13. Без перезагрузки: `POST /control/release` → через 20–45 с тост «ДТП на въезде в Новотитаровскую», бейдж «1 новое».
14. «Почему здесь?»: станица Новотитаровская, фрагмент «Новотитаровскую», 1 из 1 источников.

Тест требует свежего стенда (проверяет предусловие) и падает, если после выбора результата поиска
снова открывается выпадающий список (регрессия, найденная в этой сессии).

## Геолокация: что покрывает golden-набор

Омонимы (Ивановка ×18, Paris FR/US, Moscow RU/ID, Springfield); «в 15 км от Краснодара»; «под Краснодаром»;
улица с названием города («ул. Ростовская»); клубы с названием города («ФК «Краснодар»»); регион без города
(«по всему краю»); несколько мест в одной статье; отсутствие места; координаты в тексте; аппозиции
(«Moscow, Idaho»); падежи ru/uk; de, fr, es, it, zh. После каждого исправления набор прогонялся целиком.

Единственный сквозной промах — `dier-4`: немецкая деревня Dierfeld (7 жителей), упомянутая **по-русски**
(«Дирфельд»). В офлайн-данных у неё нет русского названия, а транслитерационного нечёткого поиска пока нет.
Из-за этого же сообщения событие распалось на два (единственный split в B-cubed).

## Red team: найдено и исправлено

**Геолокация и конвейер**
- «Краснодарского края» не распознавалось (строчное «края») → слова-типы в продолжении n-граммы.
- Город и одноимённая админ-единица конкурировали → общий референт, а не соперники.
- Клубы в кавычках («ФК «Краснодар»», «Ростов») → признак организации и слабая связь `about`.
- «Moscow, Idaho» → аппозиции.
- Расстояние из другого упоминания терялось → привязка признаков к упоминанию.
- Улица без слова «улица» («на Красной»), перечни улиц.
- «На окраине» ошибочно считалось «рядом» → окраина = внутри места.
- «Ивановка» без контекста → высокая неоднозначность, на карту не ставится.
- Межъязыковые пары не сходились → фонетические ключи имён, бонус места при разных языках.
- Официальное «возгорание ликвидировано» и «загорелся дом» не склеивались → совпадение типа события снимает вето по тексту.
- Отключение света путалось с происшествиями → тип `utility_outage` в «Обществе».
- Склеенный заголовок Telegram, форварды с другим хвостом → кандидаты по заголовку.
- Копия, обработанная раньше оригинала → разворот направления.
- Независимые источники считались вместе с пересылками → независимость только по оригинальному контенту.
- Ежедневный прогноз одного источника склеивался со вчерашним (онлайн и в фоновом слиянии) → правило регулярной рубрики (общая функция).
- Сломанный XML давал «0 записей» вместо ошибки → `FetchError`, источник виден как неисправный.

**Интерфейс**
- Воркер MapLibre не грузился в dev → `setWorkerUrl`; **в прод-сборке** он же давал 404 на общий чанк (`?url`) → `?worker&url`.
- Высота контейнера карты 0; цвета и палитра не применялись при загрузке; наложение подписей пузырей.
- Пузырь «Россия» стоял в Сибири → центр как среднее единичных векторов из rollup.
- «станица» показывалась как «Город»; бейдж языка при совпадающем языке; просвечивающая панель; «1 новых».
- После выбора результата поиска список открывался снова и закрывал центр карты.
- Подпись подложки дублировала подпись пузыря («Краснодар» дважды, «РОССИЯ» под «Россия») → базовые подписи мест с пузырём скрываются фильтром.
- На телефоне нельзя было переключить язык (кнопка скрыта), а поиск не сжимался и выталкивал кнопки за край → скрывается декоративный логотип, поиск сжимается; проверено на 360 и 390 px.
- Тост о новом событии не приходил из-за узкого bbox подписки → live-зона с запасом вокруг вьюпорта.

**Карта и геоданные** (найдено на скриншотах этой сессии)
- Тайлы у антимеридиана выбирали противоположное полушарие: рамка с отступом переводилась в 4326 и
  заворачивалась (183,6° → −176,4°). На z1 пропадала почти вся Евразия и Африка, на любом зуме — крайние
  столбцы тайлов (Чукотка, Камчатка, Фиджи). Регрессионный тест падал до исправления.
- Полигоны world-atlas сшиты через антимеридиан; плоское чтение давало полосы через полмира (площадь
  России 20,3 млн км² вместо 17,0 млн, кольца у полюса). Теперь долготы разворачиваются, полярные кольца
  замыкаются через полюс, разрез идёт по ±180 через `ST_WrapX`. После переимпорта: Россия 16,97 млн км²,
  Германия 357 тыс., Фиджи 18,3 тыс.
- Тайлы южного полушария отдавали 500 **только в Docker**: Антарктида теперь доходит до полюса, а PROJ 7.2
  в образе postgis падает на ST_Transform(−90°) (локальный PROJ 9.4 молча возвращал y ≈ −2,4·10⁸ м). Геометрия
  обрезается рамкой тайла в пределах широт Mercator (±85,0511°) до трансформации; заодно большие полигоны
  не трансформируются целиком для каждого тайла.

**Безопасность и легальность**
- XSS через `javascript:`-ссылки в фидах → наружу только http(s) (`safe_url`) и на сервере, и в UI.
- Разметка в заголовках → заголовок проходит через `html_to_text`.
- SSRF через ссылки HTML-листинга → только ссылки того же сайта и только http(s).
- robots.txt при 5xx или недоступности хоста считался разрешающим → по RFC 9309 теперь это полный запрет (тест падал до исправления).
  Перепроверка через 60 с: при 10 минутах сборщик, стартовавший на секунду раньше стенда, из-за backoff простаивал
  до ~20 минут. `devctl` теперь запускает стенд раньше сборщика.
- У кнопки очистки поиска была подпись «Закрыть» (экранные дикторы называли её неверно, e2e-тест нажимал её вместо
  закрытия карточки) → «Очистить поиск».
- Квадратичный самоджойн в фоновом слиянии → инкрементальное слияние по недавно изменённым событиям.

**Развёртывание** (найдено при первом запуске в Docker)
- Healthcheck БД срабатывал на временном init-сервере образа postgis (unix-сокет) → проверка по TCP.
- При обычной установке пакета миграции `.sql` в образ не попадали → `package-data`.
- `apk` недоступен в песочнице → скрипт данных переписан на POSIX sh.
- `devctl.sh start` без аргументов не запускал `maintenance` (фоновое слияние и очистку).
- Nginx разрешал имя `api` один раз при старте: после пересоздания контейнера API веб отдавал 502 → разрешение
  через DNS Docker на каждый запрос. Проверено принудительной сменой IP API (172.18.0.5 → 172.18.0.7) без
  перезапуска web.

## Отказоустойчивость источников

- «Нестабильный» источник (503): экспоненциальный backoff, после восстановления снова опрашивается в
  непрерывном режиме. Баннер «N из 21 источника временно недоступны».
- «Сломанный XML»: ошибка фиксируется у источника, конвейер не падает.
- Межъязыковая пара, обработанная в «неудобном» порядке («Вибух у Києві» раньше английских сообщений), может
  сначала дать два события; фоновое слияние склеивает их за ~30 с (наблюдалось: событие 10 влито в 12).
- Все источники недоступны (devstand остановлен): все 21 источник помечены неисправными, API отвечает `ok`,
  карта и ленты работают на собранных данных, баннер «21 из 21 источника временно недоступны».

1 050 000 событий (из них 50 000 в Москве), один процесс uvicorn, 4 общих ядра. Холодный запрос / из кэша агрегатов:

| Запрос | Время |
|---|---|
| Континенты | 51 / 5 мс |
| Страны за 7 дней | 246 / 18 мс |
| Регионы Европы за 24 ч | 237 / 63 мс |
| Регионы за 7 дней с фильтром категорий | p50 360, p95 637 мс / 74 мс |
| Населённые пункты по bbox | 96 / 12 мс |
| Плотный город (Москва, 50 тыс. событий) | ≈213 мс |
| Лента Москвы (keyset-пагинация) | 110–146 мс |
| Поиск мест | ≈10 мс |
| Векторный тайл подложки | ≈2 мс |
| Смешанная нагрузка, 8 параллельных клиентов | 21,5 запроса/с |
| Массовое удаление 1 млн событий | 30 с (было >20 мин до индекса на `event.merged_into`) |

До rollup глобальные агрегаты на том же объёме занимали секунды. Самый медленный запрос — окно 7 дней с
фильтрами без кэша (p95 637 мс). Следующий шаг для него — дневной rollup.

## Что не проверено

- Реальные источники (`sources.example.yaml`): сеть закрыта, ни один URL не открывался.
- Полный импорт GeoNames (`import-geonames`): проверен тестом на файлах формата GeoNames, включая
  хутор на 50 жителей, но не на настоящем дампе.
- Мобильные устройства: проверены ширины 360 и 390 px в Chromium, реальные телефоны — нет.
- Длительная работа (сутки и больше) и несколько процессов API под нагрузкой.
- Тёмный «застывший» прямоугольник в панели при плавной прокрутке: пойман 2 раза примерно за 10 записей в headless
  Chromium с программным рендерингом (SwiftShader). В DOM такого элемента нет; 6 контрольных прогонов (с
  `backdrop-filter` и без) чистые. Вероятно, это артефакт программного композитинга; на реальной GPU не проверялось.

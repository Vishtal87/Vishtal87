# Исследование технологий и обоснование выбора

Дата: 2026-09-25. Всё ниже проверено в текущем окружении, а не взято из памяти.
Где проверка невозможна (сеть закрыта), это сказано явно.

## 0. Аудит исходного состояния

- Репозиторий `Vishtal87/Vishtal87` был пуст (0 коммитов), поэтому проект greenfield. Переиспользовать нечего, ломать тоже нечего.
- Окружение: Node 22 + pnpm, Python 3.11, PostgreSQL 16, PostGIS 3.4 (из apt), redis-server, Chromium для Playwright. 4 CPU, 15 ГБ RAM.
- Сеть (egress-политика песочницы). Открыты npm, PyPI, GitHub, apt. Закрыты (HTTP 403 на CONNECT):
  download.geonames.org, nominatim/overpass/geofabrik (OSM), t.me, youtube.com, news.google.com,
  api.gdeltproject.org, RSS СМИ (BBC, TASS, РИА и др.), тайл-серверы (OpenFreeMap, demotiles), CDN (jsdelivr, unpkg).
  Решение пользователя: строить и проверять офлайн, живые источники подключить позже.

## 1. 3D-глобус / карта

| Вариант | Плюсы | Минусы | Итог |
|---|---|---|---|
| **MapLibre GL JS 6** (`projection: globe`) | Open source (BSD). Глобус на малых зумах и плавный переход в mercator на больших. Один движок от планеты до улицы. Векторные тайлы, data-driven стили, GeoJSON/MVT-источники | 3D-рельеф ограничен (для новостей не нужен) | **Выбран** |
| CesiumJS | Настоящий 3D, рельеф | ~80 МБ пакет, тяжёлый рендер. Данные и рельеф обычно через Cesium ion (аккаунт/токен). Для слоя новостей избыточен | нет |
| globe.gl / three-globe | Красиво, three.js | Нет перехода к уровню улиц, нет картографической подложки | нет |
| Mapbox GL JS v3 | Отличный глобус | Проприетарная лицензия, токен, оплата за загрузки карты | нет |
| deck.gl GlobeView | Мощные слои | GlobeView экспериментальный, нет подложки | нет (можно поверх MapLibre позже) |

Подложка. В песочнице тайл-серверы закрыты, поэтому используется своя офлайн-подложка:
- полигоны стран Natural Earth из npm `world-atlas` (public domain);
- слой населённых пунктов как MVT, который генерирует PostGIS (`ST_AsMVT`) прямо из газеттира;
- глифы для подписей из npm `smp-noto-glyphs`.

Внешний стиль (OpenFreeMap / Protomaps PMTiles) подключается переменной окружения. Это и отказоустойчивость: карта работает без сторонних тайлов.

## 2. Геоданные, газеттир, геокодирование

| Источник | Что даёт | Лицензия | Доступность здесь |
|---|---|---|---|
| **GeoNames** full dump (`allCountries`, `CC.zip`, `alternatenames/`) | 12M+ объектов, все PPL (включая хутора и деревни), PPLX (районы города), ADM1–ADM5, стабильные id, языковые altnames | CC-BY 4.0 | закрыто (нужна сеть); импортёр написан и покрыт тестом на файле того же формата |
| GeoNames `cities500` (PyPI `geonamescache`) | 234 908 н.п. (нас. ≥500 и все центры админделений до PPLA4, в т.ч. коммуны FR/IT/ES/DE с нас. 2–100), многоязычные altnames без языковых тегов | CC-BY 4.0 | **есть** |
| npm `cities.json` | названия admin1 (3 865) и admin2 (47 643) по кодам GeoNames | CC-BY 4.0 | **есть** |
| npm `iso3166-2-db` | названия стран и регионов на ru/en/de/fr/es/zh/… со ссылками на GeoNames/OSM id | MIT (данные OSM/GeoNames) | **есть** |
| OpenStreetMap (osm2pgsql / Nominatim / Photon) | улицы, полигоны границ, `place=hamlet`, `official_status` (станица/хутор) | ODbL | закрыто. Nominatim на весь мир ≈ 1 ТБ и дни импорта, поэтому идёт позже как адаптер уровня улиц |
| Who's On First / geoBoundaries | иерархия и полигоны | CC-BY / CC-BY | закрыто, кандидат для полигонов admin |

Вывод: **собственный газеттир в PostGIS**. Модель источников расширяема (`source` = geonames|osm|wof),
иерархия универсальна (`kind` = continent/country/admin1..5/locality/sublocality/street/point), а местные
типы («станица», «Gemeinde») хранятся как данные (`local_type`). Внешний геокодер как основа не подходит:
лимиты, сеть, отсутствие контроля над омонимами и контекстом источника.

Офлайн-ограничение. По Краснодарскому краю в офлайн-бандле 234 н.п. из ~1 700, у РФ нет admin2 и нет полигонов регионов.
Полная база подключается одной командой: `scripts/fetch_geonames.sh RU && geonews import-geonames RU`.

## 3. NLP без LLM (решение пользователя)

| Задача | Выбор | Проверено |
|---|---|---|
| Морфология ru/uk | `pymorphy3` + dicts | «в Горячем Ключе» → «горячий ключ», «в станице Динской» → «динской» (= лемма «Динская»), «Ростове-на-Дону» → «ростов-на-дон» |
| Язык | `lingua-language-detector` (ограниченный набор языков, модели предзагружаются при старте воркера) | ru/uk/en/de/fr/es/zh определяются верно на коротких фразах; первый вызов ~1–3 с (ленивая загрузка) |
| Извлечение текста из HTML | `trafilatura` | стандарт де-факто |
| RSS/Atom | `feedparser` | стандарт де-факто, ETag/Last-Modified |
| Даты и относительное время | `dateparser` + свои правила | многоязычный |
| NER | natasha **отвергнута**: зависит от pymorphy2, который не работает на Python 3.11 | — |

Геолокация построена на **газеттире**: n-граммы текста → леммы → индексный поиск в `geo_name`, дальше
скоринг кандидатов по контексту. Такой подход не зависит от языка модели NER и находит даже
неизвестные NER-моделям хутора.

## 4. Дедупликация и кластеризация

- Точные дубли: канонический URL и SHA-256 нормализованного текста.
- Near-dup (форварды, перепосты): **SimHash-64** хранится в `bigint`, плюс 4 band-колонки по 16 бит с индексами.
  Кандидаты ищутся по совпадению хотя бы одного бэнда (при расстоянии Хэмминга ≤3 бэнд совпадёт гарантированно,
  принцип Дирихле), затем точная проверка Jaccard по шинглам.
  datasketch/MinHash-LSH **отвергнут**: индекс живёт в памяти одного процесса и не шарится между воркерами.
- Кластеризация событий: онлайн single-pass с blocking (время ±72 ч, место, категория) и составной скор
  (место, время, категория, косинус лемм, числа). Место — это id из газеттира, он не зависит от языка,
  поэтому RU/EN/DE-статьи об одном событии сходятся без перевода. Периодически запускается merge близких событий.
  Эмбеддинги (sentence-transformers) требуют HuggingFace, который закрыт. Интерфейс оставлен, чтобы добавить их позже.

| Вариант | Итог |

## 6. Realtime

Потребность: сервер пушит клиенту новые и обновлённые события внутри его вьюпорта и фильтров. Поток
**односторонний**. Смена вьюпорта случается редко и реализуется переподключением с новыми параметрами.

- **SSE** выбран: обычный HTTP, проходит прокси, автоматический реконнект и `Last-Event-ID` в браузере.
  Resume идёт по таблице `event_change_log`.
- Источник событий: Postgres `LISTEN/NOTIFY` из воркера в API-процессы. Каждый процесс API держит один LISTEN и
  раздаёт события подписчикам, фильтруя по bbox, категориям и типам источников.
- WebSocket не нужен: двусторонний канал ничего не даёт при большей сложности (прокси, ручной реконнект).

## 7. Источники и правовая модель

| Тип | Механизм | Модель доступа |
|---|---|---|
| СМИ, региональные, муниципальные, официальные сайты | RSS/Atom | `public_feed`: фиды опубликованы для синдикации |
| Официальные и муниципальные сайты без RSS | HTML-листинг + `trafilatura` | `public_web`: только с разрешения robots.txt, rate-limit, собственный User-Agent с контактом |
| Telegram | публичная веб-витрина канала `t.me/s/<channel>` (без логина) или MTProto API с ключами владельца | `public_web` / `official_api` |
| YouTube | официальный RSS канала `feeds/videos.xml?channel_id=` | `public_feed` |
| GDELT DOC 2.0 | открытый API | `official_api` |

Мы никогда не обходим авторизацию, paywall и технические ограничения. Пользователю показываются заголовок,
короткий отрывок (≤300 символов) и ссылка на оригинал. Сырой payload хранится ограниченно
(`GEONEWS_RAW_RETENTION_DAYS`) только для аудита происхождения.

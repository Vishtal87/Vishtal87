# Источники: модель доступа и правила

## Принципы

1. **Только легальный доступ.** RSS/Atom, опубликованные для синдикации; документированные открытые API;
   публичные страницы, которые robots.txt разрешает читать. Никакого обхода авторизации, paywall,
   капчи и технических ограничений.
2. **Понятная модель получения данных у каждого источника.** Поле `access_model` в реестре обязательно
   (ограничение в БД): `public_feed`, `official_api`, `public_web`, `partner` (по договору). Рядом лежит
   `legal_note`.
3. **Не перепечатываем статьи.** Пользователь видит заголовок, отрывок ≤300 символов и кнопку «Открыть
   оригинал». У каждого сообщения в событии есть ссылка на первоисточник. Полный текст нужен только для
   анализа и лежит в БД. Сырой ответ источника удаляется через `GEONEWS_RAW_RETENTION_DAYS`
   (по умолчанию 30 дней).
4. **Вежливый сборщик** (`ingestion/fetcher.py`):
   - собственный User-Agent с контактом (`GEONEWS_USER_AGENT`);
   - robots.txt проверяется перед каждым хостом по RFC 9309. 4xx — правил нет. 5xx или хост недоступен —
     **считаем, что всё запрещено**, и перепроверяем через 10 минут;
   - не чаще одного запроса в секунду на хост (`GEONEWS_HOST_INTERVAL_S`);
   - условные запросы (ETag / If-Modified-Since → 304), ограничение размера ответа 5 МБ, тайм-аут 15 с;
   - неудачи дают экспоненциальный backoff до 6 ч. Здоровье источника видно в `/api/health` и в
     баннере интерфейса.
5. **Быстрое отключение.** `enabled: false` в реестре и `geonews load-sources` — источник больше не
   опрашивается. Уже собранные материалы остаются связанными с оригиналом ссылкой.

## Типы источников и коннекторы

| Тип (`source_type`) | Коннектор | Как получаем | Модель доступа | Что храним / показываем |
|---|---|---|---|---|
| СМИ федеральные, региональные, местные, ТВ (`media`, `regional_media`, `local_media`, `tv`) | `rss` (RSS 2.0 / Atom через feedparser, georss-координаты) | фид, опубликованный издателем | `public_feed` | заголовок, анонс из фида, отрывок, ссылка |
| Официальные ведомства и муниципалитеты (`official`) | `rss`, если есть фид; иначе `html_list` | фид или публичный список новостей: ссылки берутся только с того же сайта и только http(s), текст извлекает `trafilatura` | `public_feed` / `public_web` | отрывок, ссылка; метка «официальный источник» |
| Telegram (`telegram`) | `telegram_public` | публичная веб-витрина канала `t.me/s/<канал>`, доступная без входа | `public_web` | текст поста (первая строка — заголовок), отрывок, ссылка на пост |
| YouTube (`youtube`) | `youtube_rss` | официальный RSS канала `youtube.com/feeds/videos.xml?channel_id=` | `public_feed` | название и описание видео, ссылка |
| Агрегаторы (`aggregator`) | `gdelt` | GDELT DOC 2.0 API (`mode=artlist`): только заголовки и ссылки, страницы издателей не скачиваются | `official_api` | заголовок, ссылка |
| Блоги, UGC, организации (`blog`, `ugc`, `organization`) | `rss` / `html_list` | как выше | `public_feed` / `public_web` | как выше; UGC без подтверждения получает метку «не подтверждено» |

Поле `trust_tier` (1 — официальный … 4 — анонимный) берётся по типу источника по умолчанию и может быть
переопределено. Оно влияет на метку доверия и на выбор заголовка события, но **не** на
«истинность»: интерфейс всегда подписывает «это не подтверждение достоверности».

## Что сознательно не делается

- Нет входа в аккаунты и нет MTProto-клиента Telegram с чужими ключами. Работа через MTProto API с
  собственными ключами и по правилам Telegram — возможное расширение, в MVP не реализовано.
- Не используются X/Twitter, VK, Facebook, Instagram: их API платные или закрытые, а публичные страницы
  требуют входа.
- Нет скрапинга страниц, которые robots.txt запрещает, и страниц за paywall.
- Полные тексты чужих статей пользователю не показываются.

## Реестры

- **`backend/config/sources.demo.yaml`** — 21 **синтетический** источник на демо-стенде `devstand`
  (`synthetic: true`, в интерфейсе висит баннер «Демо-режим»). Стенд имитирует форматы RSS, Atom,
  `t.me/s`, YouTube feed, HTML-сайт и GDELT JSON. Он же умеет выпускать live-записи
  (`POST /control/release`), инъецировать сбои (`/control/fail?slug=…&mode=503|timeout`) и отдавать
  gold-разметку для оценки (`/control/gold`). Среди источников есть намеренно сломанные: «нестабильный»
  (503 → восстановление) и «сломанный XML».
- **`backend/config/sources.example.yaml`** — 13 **реальных** источников:
  - BBC World и BBC Russian, tagesschau, Le Monde, ТАСС, РИА Новости, Коммерсантъ;
  - USGS (землетрясения, georss) и GDACS (бедствия);
  - GDELT;
  - шаблоны для Telegram-канала, YouTube-канала и официального сайта без RSS.

  **Все выключены** (`enabled: false`): из среды разработки внешняя сеть закрыта, поэтому ни один URL
  не проверен.

### Как включить реальный источник

1. Откройте URL и убедитесь, что это действующий фид или публичная страница без входа.
2. Проверьте robots.txt и условия использования сайта; при необходимости запишите их в `legal_note`.
3. Укажите домашнее место (`home: {q, cc, kind}`) для местных источников: это главный сигнал
   для разрешения омонимов («Ивановка» в канале района).
4. Поставьте `enabled: true`, выполните `geonews load-sources sources.example.yaml` (или задайте
   `GEONEWS_SOURCES`), затем проверьте `/api/health` и логи ingest-воркера.

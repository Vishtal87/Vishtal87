# Источники: модель доступа и правила

## Принципы

1. **Только легальный доступ.** RSS/Atom, опубликованные для синдикации; документированные открытые API;
   карты сайта для новостных агрегаторов (news sitemap); публичные страницы без входа. Никакого обхода
   авторизации, paywall, капчи и технических ограничений: ответ 401/403/429 — это ошибка источника, а не
   повод подменять User-Agent или ходить через прокси.
2. **Понятная модель получения данных у каждого источника.** Поле `access_model` в реестре обязательно
   (ограничение в БД): `public_feed`, `official_api`, `public_web`, `partner` (по договору). Рядом лежит
   `legal_note`.
3. **Не перепечатываем статьи.** Пользователь видит заголовок, отрывок ≤300 символов и кнопку «Открыть
   оригинал». У каждого сообщения в событии есть ссылка на первоисточник. Полный текст нужен только для
   анализа и лежит в БД. Сырой ответ источника удаляется через `GEONEWS_RAW_RETENTION_DAYS`
   (по умолчанию 30 дней).
4. **Вежливый сборщик** (`ingestion/fetcher.py`):
   - собственный User-Agent с контактом (`GEONEWS_USER_AGENT`);
   - robots.txt проверяется перед каждым хостом по RFC 9309. 4xx — правил нет. 5xx или хост недоступен —
     **считаем, что всё запрещено**, и перепроверяем через минуту;
   - исключение задаёт только владелец проекта и только для отдельного источника:
     `config: {respect_robots: false}` с объяснением в `legal_note`. Сейчас так отмечены Коммерсантъ и
     Лента.ру: проверка отклоняла их из-за robots.txt, хотя свои RSS-ленты издатели публикуют открыто. Исключение
     касается только robots.txt: блокировки (403, вход, капча) по-прежнему не обходятся. Например, ТАСС
     отвечает сборщику 403 и остаётся выключенным;
   - не чаще одного запроса в секунду на хост (`GEONEWS_HOST_INTERVAL_S`);
   - условные запросы (ETag / If-Modified-Since → 304), ограничение размера ответа 5 МБ, тайм-аут 15 с;
   - неудачи дают экспоненциальный backoff до 6 ч. Здоровье источника видно в `/api/health` и в
     баннере интерфейса.
5. **Быстрое отключение.** `enabled: false` в реестре и `geonews load-sources` — источник больше не
   опрашивается. Уже собранные материалы остаются связанными с оригиналом ссылкой.

## Типы источников и коннекторы

| Тип (`source_type`) | Коннектор | Как получаем | Модель доступа | Что храним / показываем |
|---|---|---|---|---|
| СМИ федеральные, региональные, местные, ТВ (`media`, `regional_media`, `local_media`, `tv`) | `rss` (RSS 2.0 / Atom через feedparser, georss-координаты) | фид, опубликованный издателем | `public_feed` | заголовок, анонс из фида, отрывок, ссылка |
| Официальные ведомства и муниципалитеты (`official`) | `rss`, если есть фид; иначе `sitemap_news` или `html_list` | фид или публичный список новостей: ссылки берутся только с того же сайта и только http(s), текст извлекает `trafilatura` | `public_feed` / `public_web` | отрывок, ссылка; метка «официальный источник» |
| Любой сайт без RSS, но с картой новостей (`sitemap_news`) | `sitemap_news` | news sitemap (формат Google/Яндекс Новостей) или индекс карт сайта: заголовок и дата из карты, текст со страницы статьи; берутся материалы не старше 72 ч, до 15 новых за опрос | `public_web` | как у фида |
| Любой сайт без RSS и без карты (`html_list`) | `html_list` | главная или страница «Новости»: ссылки на статьи по `config.item_xpath` или эвристикой (заголовок 25–250 символов, путь статьи, только тот же сайт), до 10 новых за опрос | `public_web` | как у фида |
| Telegram (`telegram`) | `telegram_public` | публичная веб-витрина канала `t.me/s/<канал>`, доступная без входа | `public_web` | текст поста (первая строка — заголовок), отрывок, ссылка на пост |
| YouTube (`youtube`) | `youtube_rss` | официальный RSS канала `youtube.com/feeds/videos.xml?channel_id=` | `public_feed` | название и описание видео, ссылка |
| Агрегаторы (`aggregator`) | `gdelt` | GDELT DOC 2.0 API (`mode=artlist`): только заголовки и ссылки, страницы издателей не скачиваются | `official_api` | заголовок, ссылка |
| Блоги, UGC, организации (`blog`, `ugc`, `organization`) | `rss` / `html_list` | как выше | `public_feed` / `public_web` | как выше; UGC без подтверждения получает метку «не подтверждено» |

Поле `trust_tier` (1 — официальный … 4 — анонимный) берётся по типу источника по умолчанию и может быть
переопределено. Оно влияет на метку доверия и на выбор заголовка события, но **не** на
«истинность»: интерфейс всегда подписывает «это не подтверждение достоверности».

## Что сознательно не делается

- Нет входа в аккаунты и нет MTProto-клиента Telegram с чужими ключами. Работа через MTProto API с
  собственными ключами и по правилам Telegram — возможное расширение, в MVP не реализовано.
- Не используются X/Twitter, VK, Facebook, Instagram: их API платные или закрытые, а публичные страницы
  требуют входа.
- Нет скрапинга страниц, которые robots.txt запрещает (кроме источников, для которых владелец проекта
  явно отключил robots.txt, см. выше), и страниц за paywall.
- Нет обхода блокировок: подмены User-Agent под браузер, прокси и ротации адресов.
- Полные тексты чужих статей пользователю не показываются.

## Реестры

- **`backend/config/sources.demo.yaml`** — 21 **синтетический** источник на демо-стенде `devstand`
  (`synthetic: true`, в интерфейсе висит баннер «Демо-режим»). Стенд имитирует форматы RSS, Atom,
  `t.me/s`, YouTube feed, HTML-сайт и GDELT JSON. Он же умеет выпускать live-записи
  (`POST /control/release`), инъецировать сбои (`/control/fail?slug=…&mode=503|timeout`) и отдавать
  gold-разметку для оценки (`/control/gold`). Среди источников есть намеренно сломанные: «нестабильный»
  (503 → восстановление) и «сломанный XML».
- **`backend/config/sources.ru.candidates.yaml`** — **кандидаты для запуска: Краснодарский край, затем Россия.**
  - 10 региональных СМИ Кубани (Кубанские новости, Кубань 24, Юга.ру, РБК Краснодар, КП-Кубань, АиФ-Кубань, 93.ru,
    Новая газета Кубани, Юг Times, Новороссийский рабочий);
  - 4 официальных сайта: администрации края, Краснодара и Сочи, ГУ МЧС по краю;
  - 7 федеральных СМИ (ТАСС, РИА Новости, Интерфакс, Коммерсантъ, РБК, Лента.ру, Российская газета) и МЧС России;
  - GDELT (русскоязычные заголовки).

  У региональных сайтов указана только главная страница: адрес RSS находит автопоиск. Этот файл напрямую не
  загружается, его проверяет `check-sources` (ниже).
- **`backend/config/sources.example.yaml`** — 10 международных источников: BBC World и BBC Russian, tagesschau,
  Le Monde, USGS (землетрясения, georss), GDACS (бедствия), GDELT (англоязычные заголовки), шаблоны для
  Telegram-канала, YouTube-канала и официального сайта без RSS. Все выключены (`enabled: false`).

Кандидаты проверены на сервере командой `scripts/prod.sh verify-sources`; результат лежит только на сервере
(`backend/config/sources.ru.yaml`, в git не хранится).

### Проверка и включение источников: `geonews check-sources`

```bash
geonews check-sources sources.ru.candidates.yaml --out backend/config/sources.ru.yaml
# на сервере то же самое делает: scripts/prod.sh verify-sources
```

Для каждого кандидата команда тем же сборщиком и теми же коннекторами, что и в работе:

1. проверяет robots.txt. Если он недоступен, кандидат отклоняется с пометкой «robots.txt unreachable» —
   это отличается от «disallowed»;
2. если дан только `homepage`, ищет вход в порядке «лучше → хуже» и останавливается на первом рабочем виде:
   - фиды: `<link rel="alternate" type="application/rss+xml|atom+xml">`, ссылки «RSS» на странице,
     стандартные пути `/rss`, `/feed` и т. п.;
   - news sitemap: адреса из строк `Sitemap:` в robots.txt и стандартные пути (`/sitemap-news.xml` и др.);
   - сама главная как список новостей (`html_list`): для проверки скачиваются 2 статьи;
3. битый XML в фиде (незакрытые теги, `&` без экранирования) чинится парсером lxml в режиме recover,
   а не отбрасывается;
4. выбирает самый свежий рабочий вариант; отклоняет его, если самая свежая запись старше 14 дней.

С ключом `--keep-previous` источник, который сейчас не ответил, но уже есть в выходном файле, остаётся в нём:
сайт, упавший на час, не выпадает из списка. Так работают установщик и автообновление на сервере.

Прошедшие проверку записываются в выходной файл с `enabled: true`, рабочим URL и отметкой о проверке в
`legal_note`. Если не прошёл никто, файл не создаётся: пустой реестр не должен молча запустить сайт без
источников. Выходной файл стоит просмотреть глазами перед `load-sources`.

### Сайт без RSS

`check-sources` сам подберёт `sitemap_news` или `html_list`. Если эвристика `html_list` берёт лишнее, задайте
XPath ссылок на новости в `config.item_xpath`: для каждого сайта он свой, его подбирают по разметке страницы
списка. Ссылки берутся только с того же сайта.

### Как включить реальный источник

1. Откройте URL и убедитесь, что это действующий фид или публичная страница без входа.
2. Проверьте robots.txt и условия использования сайта; при необходимости запишите их в `legal_note`.
3. Укажите домашнее место (`home: {q, cc, kind}`) для местных источников: это главный сигнал
   для разрешения омонимов («Ивановка» в канале района).
4. Поставьте `enabled: true`, выполните `geonews load-sources <файл>` (или задайте `GEONEWS_SOURCES`), затем
   проверьте `/api/health` и логи ingest-воркера. Для кандидатов то же самое делает `check-sources`.

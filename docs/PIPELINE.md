# Конвейер обработки

```
SOURCE → RAW → NORMALIZATION → LANGUAGE → TEXT → DATE/TIME → GEOLOCATION → PLACE RESOLUTION
       → EVENT EXTRACTION → CATEGORY → DEDUP → EVENT CLUSTERING → DB → MAP/FEED
```

Каждая стадия — функция `pipeline/*.py`. Оркестратор `pipeline/runner.py` (`Processor.process_raw`) пишет
результат каждой стадии в `article_analysis` (стадия, метод `rules-v1`, версия, JSON). Исходные данные не
меняются: `raw_item` → `article` → анализ.

| Стадия | Модуль | Что делает |
|---|---|---|
| RAW | `ingestion/connectors/*` | запись ленты или поста как есть (`raw_item`), внешний id, URL |
| NORMALIZATION / TEXT | `normalize.py` | HTML → текст (блочные теги → переносы), `trafilatura` для полных страниц, NFC, канонический URL (без utm/fbclid/amp/m.), только http(s)-ссылки, отрывок ≤300 символов |
| LANGUAGE | `language.py` | `lingua` на ограниченном наборе языков (`GEONEWS_LANGUAGES`) |
| DATE/TIME | `dates.py` | `published_at` в UTC; фид без часового пояса → пояс источника (`published_tz_assumed`). `event_time` из «вчера вечером», «прошлой ночью», «в 13:40», «in der Nacht», «anoche». Метки «N лет назад», «годовщина» и материалы старше 72 ч → `is_live = false` |
| GEOLOCATION, PLACE RESOLUTION | `geoparse/` | см. ниже |
| EVENT EXTRACTION, CATEGORY | `classify.py` + `config/categories.yaml` | 13 расширяемых категорий с многоязычными ключевыми словами; тип события (`fire`, `road_accident`, `utility_outage`, …) |
| DEDUP | `dedup.py` + `runner._dedup` | см. ниже |
| EVENT CLUSTERING | `clustering.py`, `runner._cluster`, `merge.py` | см. ниже |
| TRUST, сборка события | `trust.py`, `event_builder.py` | метка доверия, консенсус места, заголовок и краткое содержание |

## Геолокация

Цель — не «найти любое слово-топоним», а понять, **где произошло событие**, насколько мы в этом уверены
и почему.

**1. Упоминания** (`geoparse/mentions.py`). Текст разбивается на токены, из них строятся n-граммы (1–4).
Ключи n-грамм нормализуются той же функцией, что и названия в газеттире: casefold, без диакритики,
лемма pymorphy3 для ru/uk. Поэтому «в станице Динской» даёт ключ «динская». Для китайского и японского
используется поиск подстрок. Для каждого упоминания собираются признаки контекста:

- слово-тип: «станица», «хутор», «деревня», «village of», «Gemeinde», «commune de», «район», «область»;
- локативный предлог («в», «под», «near», «bei», «à»);
- расстояние и направление: «в 15 км от», «севернее», «à 20 km de»;
- «рядом», «под городом», «на окраине» (окраина — это *внутри* места, а не «рядом»);
- улица: «ул. Ростовская», «на Красной», «Kölner Straße», перечни улиц;
- организация: «ФК «Краснодар»», «завод …», название в кавычках;
- маршрут: «трасса Краснодар — Ростов»;
- заглавная буква в исходнике, позиция в начале предложения, похожесть на имя человека,
  нарицательное слово по pymorphy3 («Мир», «Заря»).

**2. Кандидаты.** Один индексный запрос к `geo_name` на весь документ (`gazetteer_lookup.PgGazetteer`,
LRU-кэш). Объединяются варианты по `norm` и по лемме. Более длинное совпадение поглощает вложенное
(«Нижний Новгород» ⊃ «Новгород»). Аппозиции связываются («Springfield, Illinois», «Moscow, Idaho»,
«Динская (Краснодарский край)»).

**3. Скоринг, два прохода** (`resolver._score`). Балл кандидата складывается из:

- априорной важности: население и ранг, `0.6·importance`;
- совпадения со словом-типом: +3, противоречие −3;
- аппозиции: +3,5;
- локативного предлога: +1;
- **административного контекста текста**: +4,0 или +4,5, если кандидат лежит внутри упомянутых в тексте
  региона или района;
- **зоны покрытия источника**: +3,5 внутри домашнего региона, +1,2 в стране источника, плюс близость
  к домашней точке источника, логарифмически по километрам;
- штрафов: нарицательное слово −3, имя человека −2,5, улица −6, организация −2, одиночное слово
  в начале предложения −1,5.

Первый проход идёт без контекста и определяет, какие регионы вообще упомянуты. Затем для неоднозначных
упоминаний (≥30 одноимённых или выбранный кандидат вне контекста) делается **целевой повторный запрос
кандидатов внутри найденных регионов** (`lookup_within`). Так маленькая деревня находится среди сотен
тёзок, даже если в глобальный топ по важности она не попала. Второй проход считает баллы уже с контекстом.

**4. Уверенность.** Город и одноимённая административная единица, которая его содержит, — один
референт, а не соперники. Остальные кандидаты с баллами xᵢ дают `p_best = 1 / (1 + Σ exp(xᵢ − best))`,
сила балла `σ(best − 2,2 − 0,5)`, итоговый `confidence = p_best · сила`. Порог признания топонимом —
`ACCEPT = 2.2`. `ambiguity` (1 − p_best) хранится отдельно: при `ambiguity > 0.45` событие на карту не
ставится (вся трасса при этом сохраняется).

**5. Фокус** (`_focus`). Главное место выбирается по весу упоминаний: уверенность × позиция (заголовок
+0,6, первое предложение +0,4, маршрут −0,4) × повторяемость + специфичность (точка > улица > район
города > н.п. > районы > регион > страна). Место наследует вес содержащих его регионов
(«Кубань… станица Динская»). Улицы и организации не бывают фокусом сами по себе.

**6. Решение** (`_decide`):

- «в Динской» → `relation = in`, точность = вид объекта;
- «в 15 км от Краснодара», «под Краснодаром» → `relation = near`, радиус из текста (или 5–25 км по
  умолчанию), привязка **к административной единице, содержащей ориентир, а не к самому городу**.
  Если ориентир — маленький н.п., привязка идёт к нему с отметкой «рядом»;
- новость о регионе в целом («по всему Краснодарскому краю») → `relation = region`, точность admin1.
  Она не переносится в столицу региона;
- координаты в тексте или georss → обратное геокодирование KNN до ближайшего н.п.
  (`relation = coordinates`). Координата, противоречащая тексту дальше допуска, отбрасывается;
- в тексте упомянута только организация («ФК Краснодар обыграл…») → слабая связь `about`,
  confidence ≤ 0,45;
- места нет, а источник гиперлокальный → `source_area`, confidence 0,35, с явной пометкой.

**7. Объяснение.** В `evidence` попадают фрагмент текста, кандидаты с баллами, найденный контекст и
причина решения. Интерфейс показывает это в блоке «Почему здесь?».

### Маленькие населённые пункты

1. **Нет белых списков.** Любой `geo_entity` уровня `locality` — полноценное место: у него есть страница,
   лента, пузырь на карте и собственная строка в rollup (уровень 4).
2. Маленький н.п. выигрывает у крупного тёзки за счёт контекста, а не населения: слово-тип («хутор
   Каштаны»), регион в тексте или в зоне источника, целевой запрос `lookup_within` внутри региона.
3. При кластеризации совпадение маленького места весит **больше**: в деревне на 600 жителей два
   сообщения о пожаре почти наверняка об одном и том же, а в Москве нет (`_place_strength`: 1,0 до
   20 тыс. жителей … 0,35 для городов-миллионников).
4. Если однозначно выбрать нельзя («Ивановка» без контекста: 18 тёзок), событие на карту не ставится —
   лучше пропуск, чем уверенная ошибка.
5. Офлайн-газеттир содержит н.п. от 500 жителей и все центры административных единиц, в том числе
   коммуны FR/IT/ES/DE на 2–100 жителей. Хутора и деревни РФ меньше 500 жителей появятся после
   `import-geonames RU` (импортёр проверен тестом на хуторе с населением 50).

## Дедупликация

Цель — связать копии, а не удалить их. Каждая копия остаётся в событии как отдельное сообщение
с пометкой «пересылка» или «копия».

1. **Точные копии** за 14 дней: тот же канонический URL или тот же SHA-256 нормализованного
   «заголовок + текст».
2. **Почти-копии** (форварды, перепосты, лёгкая правка). Кандидаты берутся по совпадению хотя бы одного
   из четырёх 16-битных бэндов SimHash-64 (за 7 дней) и по совпадению заголовка (за 3 дня). Второй канал
   нужен для коротких Telegram-постов, где SimHash шумит. Решает Jaccard по шинглам из 3 слов, порог
   **≥ 0,72**.
3. **Направление.** Оригиналом считается более ранняя публикация. Если копия пришла раньше оригинала
   (обработка не по порядку), связь разворачивается (`set_origin`).
4. **Регулярная рубрика.** Один и тот же источник с похожим текстом через ≥18 ч (ежедневный прогноз,
   утреннее приветствие) — это **не дубль** и не одно событие.
5. Та же публикация с изменённым содержимым сохраняется как новая `raw_item` плюс `article_version`,
   поэтому в таймлайне видны правки.

Копии получают общий `origin_group_id`. Для доверия это один источник: 10 пересылок одного поста ≠
10 подтверждений.

## Кластеризация событий

**Онлайн, один проход** (`runner._cluster`). Статья с местом (confidence ≥ 0,2, ambiguity ≤ 0,45)
сравнивается с активными событиями-кандидатами: последнее сообщение не старше 72 ч, тот же н.п. или
тот же регион или точка в пределах 60 км. Копия сразу присоединяется к событию своего оригинала.

Скор `match_score` не зависит от языка статьи:

```
0.36·место + 0.14·время + 0.12·категория + 0.08·(совпал тип события) + 0.24·косинус лемм
+ 0.06·общие числа + 0.12·общие собственные имена (фонетические ключи, RU↔EN↔DE)
+ 0.08·место, если языки разные (для межъязыковых пар решают место, время и тип)
```

- место: тот же н.п. → сила по населению (1,0…0,35). Точки ближе радиуса → 0,8, дальше 60 км → 0.
  Совпал район или регион → 0,5…0,7;
- время: `exp(−Δч / 18)`. Категории совместимы попарно (происшествия ~ криминал / погода / транспорт);
- **вето**: разрыв >72 ч; несовместимые место или категория; один язык и почти нет общих слов
  (кроме случая «тот же тип события в небольшом месте»: официальное «возгорание ликвидировано» и
  «загорелся дом» — один пожар);
- **штраф** −0,15 / −0,08: оба текста называют улицы или микрорайоны, и ни одно имя не совпало. В большом
  городе это почти наверняка разные происшествия.
- порог присоединения **0,58**. Порог консервативный: лишняя карточка лучше склейки разных событий.

Привязка сериализуется advisory-lock'ом по региону, поэтому параллельные воркеры не создают двойников.
**Фоновое слияние** (`merge.py`, каждые 30 с) ищет пары похожих событий среди изменённых за последние
15 мин с порогом 0,58 + 0,02. Оно ловит случаи, когда два источника почти одновременно открыли одно
событие. Слияние помечает событие `merged`, переносит статьи, пишет `event_relation` и уведомляет клиентов.

**Пересчёт события** (`event_builder.build_event`) после каждого изменения:

- **место — консенсус источников.** Голос каждой семьи копий взвешен её уверенностью (официальный
  ×1,5). Совместимые места поддерживают друг друга: н.п. внутри региона не спорит с регионом. Более
  точное место внутри победителя выигрывает при поддержке ≥50%. Несовместимые координаты
  отбрасываются как выбросы и видны в «Почему здесь?»;
- **заголовок** — редакционный заголовок раннего надёжного источника (СМИ предпочтительнее
  Telegram); **summary** — экстрактивный лид ≤300 символов;
- **таймлайн** — первое сообщение, пересылки, правки, обновления (например «пожар потушен»), с временем
  каждого источника.

## Доверие (`trust.py`)

Метка описывает, **кто сообщает**, а не истинность. В интерфейсе всегда есть подпись «это не
подтверждение достоверности».

| Метка | Условие |
|---|---|
| `official` | есть хотя бы один оригинальный (не пересланный) материал официального источника |
| `multiple_sources` | ≥2 независимых источника, опубликовавших **оригинальный** текст |
| `single_source` | один независимый источник |
| `unverified` | только анонимные / UGC-источники (tier 4) |

Независимость считается по источникам с оригинальным контентом: канал, который только переслал чужой
пост, добавляет охват, но не подтверждение.

- `geonews.tools.eval_geoparse`: golden-набор из 45 случаев (омонимы, «в 15 км от», улица с названием
